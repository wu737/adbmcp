# 「工具不可用」排查记录

时间：2026-11-05 上午
现象：手机端 AI 客户端报「当前模型未开启工具调用」，但 MCP 界面显示已连接。

> **最终定位：客户端是 RikkaHub，根因是 RikkaHub 侧模型记录的 `abilities` 字段为空。**
> 详见 [RikkaHub-工具调用排查](RikkaHub-工具调用排查.md)。
>
> 本文保留完整排查过程，包括中途一次**误判方向**的纠正 —— 对同类问题有参考价值。

---

## 一、排查过程（三轮）

### 第一轮：误判为 WorkBuddy

最初根据截图风格判断是 WorkBuddy 移动端，于是给出「自定义模型的工具调用开关未开启」的结论。

**这个判断是错的**，但有两项实测数据是有效的：

| 检查项 | 结果 |
|---|---|
| MCP 握手 | ✅ 200 `termux-native-mcp` v0.15.0 |
| 工具列表 | ✅ 84 个工具 |
| 工具实际调用 | ✅ `run` → `adb devices` → 返回 3 台设备 |
| 车机链路 | ✅ `.39` / `.133` 均返回 `wise` |
| 鉴权 | ✅ 固定 token 200 / 旧 token 401 / 无 token 401 |
| **模型能力** | ✅ 直连 api.deepseek.com 带 `tools` 参数 → `finish_reason: tool_calls` |

> 关键收获：**服务端与模型能力都被证明没问题**，问题一定在客户端侧。
> 这个「二分法」思路本身是对的，错的只是对客户端身份的判断。

### 第二轮：确认客户端是 RikkaHub

用户澄清用的是 RikkaHub（`me.rerere.rikkahub` v3.1.1，versionCode 194，Android 17）。

查 RikkaHub 官方文档后发现它的 MCP 是**两层结构**：

| 层 | 位置 | 状态 |
|---|---|---|
| 第一层 · 全局 MCP 服务器列表 | 设置 → MCP → termux | ✅ 已完成 |
| **第二层 · 助手绑定** | **长按助手 → 编辑 → MCP 服务器** | ❌ **未勾选** |

官方文档原文：

> 将服务器添加到 Rikka 的全局列表**并不会自动将其暴露给你的助手**。你必须为每个助手单独启用。
> 只有在此处勾选的服务器的工具才会出现在助手的工具调用中。

这解释了截图里 AI 思考过程的「no tools listed」—— 模型没收到工具定义。

### 第三轮：仍报错，源码级定位

修正助手绑定并新建对话后，**报错依旧**。继续深挖，读 `ChatService.kt` 源码找到真正的判定逻辑：

```kotlin
private fun warnIfToolsUnavailable(turn: ChatTurnContext, conversationId: Uuid) {
    if (ModelAbility.TOOL in turn.model.abilities) return   // ← 只看已保存的 abilities
    if (shouldUseExternalWebSearch(...) ||
        mcpManager.getAllAvailableTools(turn.assistant).isNotEmpty()
    ) {
        addError(IllegalStateException(context.getString(R.string.tools_warning)), ...)
    }
}
```

而 `Model.kt`：

```kotlin
val abilities: List<ModelAbility> = emptyList(),   // ← 默认空
```

**根因确定**：RikkaHub 判断模型支不支持工具调用时，看的是 DataStore 里**已保存的** `abilities` 字段，不是实时查 models.dev。该模型记录的 `abilities` 是空的。

完整分析见 [RikkaHub-工具调用排查](RikkaHub-工具调用排查.md)。

## 二、排查方法论沉淀

### 有效的二分法

把链路拆成四层，逐层验证：

```
客户端 →(tools 定义)→ 模型 API
   ↓
AI 客户端组装请求
   ↓
MCP 服务端 (tools/list, tools/call)
   ↓
adb → 车机
```

**服务端全绿 + 模型能力全绿 = 问题必在客户端组装层。** 这个判断不需要猜。

### 报错文案的语义

RikkaHub 官方 Issue #276 里作者 re-ovo 的解释最精准：

> 因为你用了需要工具调用的功能：搜索/记忆/MCP，但是模型不支持工具调用

「你用了需要工具调用的功能」是关键 —— **只要助手绑了 MCP 或开了搜索，这条警告就会出现**，它是无条件的前置检查结果，不代表模型真的不能调工具。

### 源码比文档可靠

RikkaHub 的报错文案「请在设置内启用模型的工具能力」指向模型设置，但**读源码才发现真正的开关在提供商的模型编辑弹窗里**（`ModalAbilitySelector`），而不是助手设置页。两处位置不同，容易找错。

## 三、顺带发现的两个问题

### 1. 手机无线调试会因息屏断开

排查过程中手机 `192.168.110.13:5555` **多次转为 offline**，`adb connect` 超时（10060）。

对策：
- Termux 里 `termux-wake-lock`（需 `pkg install termux-api`）
- 手机设置里把 Termux 电池优化设为「无限制」
- 或改用 USB（adb over USB 不受休眠影响，且更快）

### 2. MCP `run` 工具对长命令返回空

含 `;` 的长复合命令常返回 `(empty)`，短命令正常。
排查时改用**分步执行 + `screencap` 截图核对**，比依赖返回值可靠。

---

## 四、最终修复

两个都要做，缺一仍会报错：

1. **模型能力**：设置 → 提供商 → DeepSeek → 模型 → `deepseek-flash` → 基本设置 → 打开「工具调用」
2. **助手绑定**：长按助手 → 编辑 → MCP 服务器 → 勾选 `termux` → **新建对话**
