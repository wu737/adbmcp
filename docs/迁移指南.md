# adbmcp 迁移指南 —— 换新手机部署

## 一句话

把 `adbmcp-bundle.zip` 传到新手机 Termux 里解压，跑一次 `install-adbmcp.sh` 就完事。
**Token 固定不变，AI 客户端配置不用改，只改 IP。**

---

## 新手机需要准备

| 项 | 要求 | 说明 |
|---|---|---|
| Termux | 必装 | 从 F-Droid 或 GitHub 装，**不要用 Play 商店的旧版** |
| Android 版本 | 7.0+ | `minSdk 26`；无线调试需要 Android 11+ |
| 网络 | 与车机同一局域网 | 或手机连车机热点 |

**Termux:Boot**（可选但推荐）—— 开机自动拉起 MCP，需单独装 APK。

---

## 部署步骤

### 1. 装 Termux 后先跑一次初始化

首次打开 Termux 会自动装环境，等它跑完。

### 2. 把 bundle 传进 Termux

任选一种：

**A. 用 USB（推荐，最快）**
```bash
# PC 端
adb push adbmcp-bundle.zip /sdcard/Download/
```
然后在 Termux 里：
```bash
cp /sdcard/Download/adbmcp-bundle.zip ~
cd ~ && unzip adbmcp-bundle.zip
```

**B. 局域网传输**
```bash
# PC 端起服务 (注意防火墙)
python -m http.server 8000
# Termux 里
wget http://<PC_IP>:8000/adbmcp-bundle.zip
cd ~ && unzip adbmcp-bundle.zip
```

**C. 手动粘贴**
Termux 里 `cat > ~/install-adbmcp.sh`，把脚本内容贴进去保存。

### 3. 执行安装

```bash
cd ~
bash install-adbmcp.sh
```

脚本会依次完成：

| 步骤 | 动作 |
|---|---|
| 1/5 | `pkg install android-tools`（adb）+ `pip install termux-mcp==0.15.0` |
| 2/5 | 部署脚本到 `~/bin` 和 `~/mcp-servers/car/`，配置 PATH、开机自启 |
| 3/5 | 创建/沿用车机清单 `cars.txt` |
| 4/5 | 启动 MCP + 连接车机，打印接入信息 |
| 5/5 | 扫描本网段找出所有开 5555 的设备 |

### 4. 填车机清单

编辑 `~/mcp-servers/car/cars.txt`：
```
192.168.43.1:5555    车机热点网关
192.168.110.39:5555  车机 - Buildroot/wise
```
然后 `adbmcp restart`。

### 5. 更新 AI 客户端配置

**Token 不变，只有 URL 里的 IP 要改。**

RikkaHub / Claude / Cursor / WorkBuddy 等：
```json
{
  "type": "streamableHttp",
  "commonOptions": {
    "name": "termux",
    "enable": true,
    "headers": [
      ["Authorization", "Bearer adbmcp-K60Pro-2026-fixed-8f3a9c2e"]
    ]
  },
  "url": "http://<新手机IP>:8081/mcp"
}
```

用 `adbmcp config` 可直接打印现成配置。

## 新手机上的常用命令

```bash
adbmcp              # 启动 + 打印接入信息
adbmcp status       # 看状态
adbmcp config       # 打印 AI 客户端配置 JSON
adbmcp scan         # 扫描车机
adbmcp restart      # 重启
adbmcp stop
```

## 依赖清单（安装脚本会自动处理）

| 依赖 | 版本 | 安装方式 | 必需 |
|---|---|---|---|
| Termux | ≥ 0.118 | F-Droid / GitHub | ✅ |
| android-tools (adb) | 37.0.0 | `pkg install android-tools` | ✅ |
| python | 3.14.x | `pkg install python` | ✅ |
| termux-mcp | 0.15.0 | `pip install termux-mcp==0.15.0` | ✅ |
| Termux:Boot | — | 单独 APK | 可选（开机自启） |

> `termux-mcp` 是纯 Python 包（`py3-none-any`），PyPI 上可直接装，不挑架构。

---

## 换手机后必须改的两处

| 项 | 改不改 |
|---|---|
| **URL 里的 IP** | ✅ 必须改（新手机 IP 不同） |
| **Bearer Token** | ❌ 不用改（固定值 `adbmcp-K60Pro-2026-fixed-8f3a9c2e`） |

如果想换 token：
```bash
export ADBMCP_TOKEN=<新值>
adbmcp restart
```
然后同步更新所有 AI 客户端的配置。

## 稳定性提醒（实测踩过）

### 1. 无线调试会因息屏断开

实测排查过程中，手机 `192.168.110.13:5555` 多次转为 **offline**，`adb connect` 直接超时。

**对策：**
- Termux 里跑 `termux-wake-lock` 防止被挂起（装 `termux-api` 后可用）
- 或改用 **USB 连接**（adb over USB 不受休眠影响，且更快）
- 或在手机设置里把 Termux 电池优化设为「无限制」

### 2. MCP 服务本身也会僵死

`termux-native-mcp` 进程和 8081 监听会一起消失（表现：隧道还在但连接被 reset）。

**对策：** `car_watchdog.sh` 守护每 20 秒自愈，已随 bundle 部署。

### 3. 车机 IP 会变

车机热点网关 IP 每次可能不同。用 `adbmcp scan` 重扫并更新 `cars.txt`。

## 从旧手机直接迁移（不想重装）

如果旧手机还在、Termux 能用，最省事的是**直接复制**：

```bash
# 旧手机
cd ~/mcp-servers/car && tar czf ~/adbmcp-car.tar.gz adbmcp car_setup.sh scan_car.py car_watchdog.sh boot_car_mcp.sh cars.txt

# 传到新手机后
cd ~ && tar xzf adbmcp-car.tar.gz
cp adbmcp-car/mcp-servers/car/* ~/mcp-servers/car/ 2>/dev/null
cp adbmcp-car/adbmcp ~/bin/
chmod +x ~/bin/adbmcp ~/mcp-servers/car/*.sh
```

但**新手机仍需自己装依赖**（adb / python / termux-mcp），因为那是系统级的。

## 目录结构（部署后）

```
~/bin/
└── adbmcp                      ← 主脚本, PATH 里, 直接敲 adbmcp
~/mcp-servers/car/
├── adbmcp                      ← 主脚本副本
├── car_setup.sh                ← 手动连车机
├── scan_car.py                 ← 网段扫描找车机
├── car_watchdog.sh             ← 守护 (MCP + 车机连接)
├── boot_car_mcp.sh             ← 开机自启入口
├── cars.txt                    ← 车机清单
├── mode                        ← 模式持久化 (0.0.0.0 / 127.0.0.1)
├── mcp-endpoint.json           ← 自动生成的接入配置
├── adbmcp.log / mcp.log / watchdog.log
└── termuxGPT/                  ← 快照与回收站
~/.termux-mcp/token             ← 服务端 token 文件 (实际用环境变量, 会被清理)
~/.termux/boot/boot_car_mcp.sh  ← 开机自启
~/.bashrc / ~/.profile          ← PATH 配置
```
