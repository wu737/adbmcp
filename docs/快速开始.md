# adbmcp —— 手机 Termux 一键启动的 MCP 车机通道

在手机 Termux 里敲 `adbmcp`，MCP 服务 + ADB 车机通道即刻就绪，**同一网络下任何 AI 客户端都能直接调用**。

## 一句话用法

```bash
adbmcp
```

输出会直接打印出可粘贴的 MCP 配置、访问地址和 Bearer Token。

## 拓扑

```
AI 客户端 (Claude / Cursor / WorkBuddy / 任意 MCP)
   │  http://192.168.110.13:8081/mcp
   │  Authorization: Bearer <token>
   ↓  局域网直连
手机 Termux
   ├─ termux-native-mcp v0.15.0  (0.0.0.0:8081, Bearer 鉴权)
   └─ adb 客户端 (android-tools 37.0.0)
         ↓  adb connect <车机IP>:5555
      车机 .39 / .133  (Buildroot/wise, SStar SoC)
```

## 命令一览

| 命令 | 作用 |
|---|---|
| `adbmcp` / `adbmcp start` | 启动 MCP + 连接车机 + 打印接入信息，并拉起后台守护 |
| `adbmcp status` | 查看 MCP / 守护 / adb 设备 / 接入信息 |
| `adbmcp stop` | 停止 MCP 与守护 |
| `adbmcp restart` | 重启 |
| `adbmcp config` | 只打印 MCP 配置 JSON（可直接粘贴给 AI 客户端） |
| `adbmcp token` | 显示当前 token |
| `adbmcp lan` | 切换为局域网模式（`0.0.0.0` + token，默认） |
| `adbmcp local` | 切换为仅本机模式（`127.0.0.1`，免鉴权） |
| `adbmcp scan [网段]` | 扫描网段找出所有开 5555 的设备并自动 connect |
| `adbmcp log [行数]` | 查看日志 |

## AI 客户端配置

`adbmcp config` 输出的 JSON 直接粘贴：

```json
{
  "mcpServers": {
    "adbmcp": {
      "type": "streamableHttp",
      "url": "http://192.168.110.13:8081/mcp",
      "timeout": 120000,
      "headers": {
        "Authorization": "Bearer adbmcp-K60Pro-2026-fixed-8f3a9c2e"
      }
    }
  }
}
```

**备选（跨网络）**：在 AI 客户端所在电脑执行
```bash
adb -s 192.168.110.13:5555 forward tcp:8081 tcp:8081
```
然后用 `http://127.0.0.1:8081/mcp`（仍需带同一个 Bearer token）。

## Token 策略（固定不变）

固定 token：`adbmcp-K60Pro-2026-fixed-8f3a9c2e`

### 为什么不能完全取消鉴权

服务端 `termux-native-mcp` 的 `_check_startup_guards()` 明确规定：
绑定非 loopback 地址（`0.0.0.0`）时若无 token，**直接 `sys.exit(1)` 拒绝启动**：

```
HOST is set to 0.0.0.0 (non-loopback) but no auth token is set. Refusing to start.
```

所以「取消 token」只在绑 `127.0.0.1` 时可行 —— 那样局域网就无法直连。
`adbmcp local` 即为此模式（配置里自动去掉 Authorization 头）。

### 为什么必须设两个环境变量

服务端有**两处**读 token，位置不同，缺一不可：

| 用途 | 读取位置 | 环境变量 |
|---|---|---|
| 判断"是否要求鉴权" + 启动守卫 | `mcp_config.native_auth_token()` | `TERMUX_NATIVE_MCP_AUTH_TOKEN` |
| **实际比对** token 值 | `auth.authenticate()` → `auth.master_token()` | `TERMUX_MCP_AUTH_TOKEN` |

只设前者会导致：服务能启动（日志显示 `Authentication: enabled`），
但每次请求都 **401** —— 因为比对时读的是 `~/.termux-mcp/token` 文件里的旧值。
这是本轮实测踩到的坑。

### 固定原理

`master_token()` 优先级：`TERMUX_MCP_AUTH_TOKEN` 环境变量 → `~/.termux-mcp/token` 文件。
服务端还有 `auth.rotate()` 接口可主动轮换 token，文件被删或长度 < 16 也会自动重新生成。

→ 固定 token 走**环境变量**，并由脚本每次启动时清除 `~/.termux-mcp/token`，
**token 永不改变**。

### 修改 token

```bash
export ADBMCP_TOKEN=<新值>    # 或直接编辑脚本里的 FIXED_TOKEN 默认值
adbmcp restart
```
改完需同步更新 AI 客户端配置里的 `Authorization` 头。

## 文件位置

| 位置 | 内容 |
|---|---|

| 手机 `~/mcp-servers/car/cars.txt` | 车机清单，增删车机改这里 |
| 手机 `~/mcp-servers/car/mcp-endpoint.json` | 自动生成的接入配置 |

| 手机 `~/.termux-mcp/token` | Bearer Token（0600） |
| 手机 `~/.bashrc` / `~/.profile` | 已加 `export PATH="$HOME/bin:$PATH"` |
| 手机 `~/.termux/boot/boot_car_mcp.sh` | 开机自启入口（需装 Termux:Boot 才生效） |

## 权限与安全

- 默认模式绑 `0.0.0.0:8081`，**固定 token 鉴权**
- Token 为固定字符串，通过环境变量注入，服务端无法轮换
- 无 token / 错误 token 请求均返回 **401 Unauthorized**（已实测）
- `adbmcp local` 可切回 127.0.0.1 免鉴权模式，但此时局域网内无法直连
- 模式选择持久化在 `~/mcp-servers/car/mode` 文件

## 增删车机

编辑 `~/mcp-servers/car/cars.txt`，每行 `IP:PORT  备注`：

```
192.168.110.39:5555    车机 - Buildroot/wise, SStar SoC
192.168.110.133:5555   车机 - Buildroot/wise, hostname=wise
```

改完执行 `adbmcp restart` 生效。守护每 20 秒自动重连掉线的车机。

## 已知限制

- **Termux 被杀 → MCP 进程消失**。守护能扛住 Termux 存活但 MCP 挂掉的情况；
  Termux 整体被杀则需重开 App（装 Termux:Boot 可自动拉起）
- **`ip` 命令在 Termux 无权限**（`Cannot bind netlink socket`），`/proc/net/fib_trie` 也被 Android 11+ 收紧
  → IP 探测改用 `python3` socket 方式
- **Termux 版 adb 无 `adb mdns`** → 车机 IP 靠手填或 `adbmcp scan` 扫描
- **`adb shell` 权限**：`run-as com.termux` 不可用（非 debuggable），Termux 数据目录需通过 Termux 自身进程访问
